# 核心信念（智能体优先的操作原则）

1. 人类掌舵，智能体执行。人类不直接贡献代码行。
2. 上下文是稀缺资源；给地图，不给说明书。
3. 智能体在运行时看不到的东西，对它来说不存在——知识必须进仓库并版本化。
4. 强制不变量，不微观管理实现；中央强制边界，本地允许自主表达。
5. 纠错成本低，等待成本高；反馈回路先于门禁弱化。
6. 技术债是高息贷款，小额高频偿还。
7. 遇到卡点先问：缺的是什么能力？如何让它既清晰可读又可强制执行？
8. 交互式决策必须落盘：确认过但不写进仓库的决策等于没做。

## 本项目特有

9. **性能是需求，不是优化项**：编辑器任何输入路径禁止全文重排；数据层禁止同步 IO 阻塞主线程超过防抖所需的最小工作。
10. 架构分层 `Types → Store → UI` 单向依赖（见 `ARCHITECTURE.md`），由 lint 与结构测试机械强制。
11. 密码学实现改动必须经用户确认（现有 PBKDF2 手写实现是有意的技术债，见 `docs/exec-plans/tech-debt-tracker.md`）。

> 方法论来源：OpenAI《Harness engineering: leveraging Codex in an agent-first world》(2026-02-11)，要点已内联于本项目规则文档。

## 反模式 top 5（摘自施工规则 §14）

1. 需求不明就开工——先复述确认，再动手。
2. 交互确认过但仓库没记录——决策必须落盘。
3. 用文档描述规则却不写成代码——能 linter 的不要靠文档提醒。
4. 在低吞吐/无反馈回路时弱化门禁。
5. 巨型入口文件——AGENTS.md 只做地图，≤100 行。
